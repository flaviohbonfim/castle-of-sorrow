# Optional assets

The game is fully procedural by default. Everything in this folder is an
**override**: drop a sheet in the manifest and the engine uses it; remove the
key and the procedural builder takes over again. A missing, malformed or
unreadable file never breaks the game — it just falls back.

Do not hand-edit the PNGs here. They are the output of the pipeline:

```bash
npm run assets:build      # assets-src/ -> public/assets/ + manifest.json
npm run assets:validate   # QA gate: palette, alpha, alignment, framing
npm run assets:selftest   # end-to-end proof on a throwaway copy
```

The full plan and the reasoning behind each step is in
[docs/ART_PIPELINE.md](../../docs/ART_PIPELINE.md).

## Manifest

`public/assets/manifest.json`:

```json
{
  "version": 2,
  "sheets": {
    "skeleton.walk": {
      "file": "skeleton.png",
      "frameW": 16,
      "frameH": 32,
      "frames": 2
    }
  },
  "music": {
    "title": "music/title.ogg",
    "castle": "music/castle.ogg",
    "boss": "music/boss.ogg"
  }
}
```

### Sheet rules

- Horizontal strip of **right-facing** frames. Left-facing is generated by
  flipping at load time — never author or generate it.
- Frame `i` is the rect `(i * frameW, row * frameH, frameW, frameH)`.
- Sprites are drawn centred on the hitbox and bottom-aligned, so **every frame
  of a set must share the same box** and the feet must sit on the same row.
  `assets:validate` fails on sheets that break this.
- `frames` must match what the procedural builder expects (usually 2 walk
  frames, 3 attack frames — see `src/gfx/sprites.ts`).
- All colours must come from `src/gfx/palette.ts`; alpha must be 0 or 255.

### Optional fields (manifest v2)

| Field | Default | Meaning |
| --- | --- | --- |
| `row` | `0` | Row of the frame box inside the PNG — lets several animations share one file. |
| — | — | A sheet with **fewer** frames than the procedural builder is padded by repeating the last frame (entities index frames positionally, so a short sheet used to crash the draw loop). Extra frames are kept; cycling entities use them. |
| `anchorX` | `frameW / 2` | Column that should land on the hitbox centre. Content is shifted by `frameW/2 - anchorX` at load. |
| `anchorY` | `frameH` | Row that should land on the hitbox bottom (the feet line). Content is shifted down by `frameH - anchorY`. |

Anchors exist for hand-authored art with breathing room around the figure;
sheets built by `assets:build` are already anchored, so they omit them.
Anything pushed outside the frame box by an anchor is clipped —
`assets:validate` treats that as an error.

### Music rules

- Paths are relative to `/assets/` unless they start with `/`.
- If a file fails to load, the chiptune sequencer keeps playing that track.
- Loops start after the first user keypress (browser autoplay policy).

### Tiles

`tile.<zone>.<role>`, where zone is `castle` or `tower` and role is one of:
`brick`, `floorTop`, `platform`, `pillarTop`, `pillar`, `pillarBase`,
`bgWall`, `bgWindow`, `cracked`, `gate`, `water`, `waterTop`, `door`.

Each sheet is a horizontal strip of 16×16 **variants** — the engine picks one
per cell to break up repetition. This is not an autotile bitmask.
